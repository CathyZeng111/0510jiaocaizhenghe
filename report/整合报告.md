# 跨教材知识图谱整合报告

## 1. 本次整合范围

本报告基于 `textbooks/` 目录下 7 本医学教材生成，流程为：PDF 教材解析 → 单本教材知识图谱构建 → 跨教材节点对齐与压缩 → 输出 `GraphIntegrationResult`。统计结果已写入：

- `artifacts/integration_summary.json`

完整 `GraphIntegrationResult` 明细包含教材派生定义文本，按提交规范不推送到 GitHub；仓库中只保留统计摘要和报告正文。

参与整合的教材包括：局部解剖学、组织学与胚胎学、生理学、医学微生物学、病理学、传染病学、病理生理学。本次报告使用当前本地启发式图谱抽取结果生成，主要验证整合决策、压缩比和教学结构是否符合赛题要求。

## 3. 整合决策摘要

本次共生成 1340 条整合决策，其中：

- `merge = 30`：识别为重复或高度等价的节点组，合并为统一节点。
- `keep = 788`：未达到合并阈值或具有独立教学价值的节点，保留为独立节点。
- `remove = 522`：为满足 30% 压缩预算、移除低价值或冗余节点。

`merge` 决策主要来自标题、章节块、相同主题块之间的高相似度对齐。`keep` 决策数量最多，说明系统在相似但不确定时采取保守策略，避免把不同教材中的相近但不等价概念误合并。`remove` 决策主要由 `enforce_char_budget()` 根据字符预算和节点优先级触发，优先保留来源更多、层级更高、定义更完整、关系更多的节点。

## 4. 高置信合并案例

### 案例一：临床病例分析

`decision_merge_580` 将 3 个“第八节 | 临床病例分析”相关节点合并为 `kg_node_0580`，`score = 0.9742`，`confidence = 0.9742`。这些节点来自同一教材中不同章节的病例分析块，名称模式和教学功能高度一致，因此系统将其视为同一类教学内容节点进行压缩。该案例体现了系统可以识别重复的教学栏目结构，减少图谱中大量相似栏目造成的视觉噪声。

### 案例二：临床病例分析二级栏目

`decision_merge_237` 将 2 个“第七节 | 临床病例分析”相关节点合并为 `kg_node_0237`，`score = 0.9412`，`confidence = 0.9412`。这类节点虽然不一定是传统意义上的医学术语，但在教材结构中承担相同的教学任务，合并后可让教师在图谱中快速识别“病例分析”这一类教学活动，而不是被重复栏目淹没。

### 案例三：血栓形成

`decision_merge_356` 将《病理学》和《病理生理学》中“第三节 | 血栓形成”相关节点合并为 `kg_node_0356`，`score = 0.9000`，`confidence = 0.9000`。血栓形成是病理学和病理生理学都会讲解的共同主题，两个节点在名称和章节语义上高度一致，合并后保留统一概念入口，有助于学生跨教材比较“形态学病理变化”和“机制性病理生理过程”的差异。

## 5. 压缩比与内容保留分析

系统压缩目标是整合后内容总字数不超过原始节点内容字数的 30%。本次源节点字符数为 73635，预算上限为 22090，最终整合后字符数为 22084，仅低于预算 6 字，说明 `enforce_char_budget()` 已经把内容压缩到非常接近上限的位置。该策略在保留核心结构的同时尽量不浪费预算：一级章节、来源多的节点和关系密集节点会获得更高优先级；目录、出版信息、过短占位节点和低连接度节点会被删除或压缩。

需要注意的是，本次自动解析仍能看到部分目录页、出版页或栏目标题被抽成节点，例如官网、页码、泛化章节编号等。这些节点大多会被 `remove` 或预算压缩淘汰，但它们也提示后续可以继续加强解析阶段的目录过滤和知识点命名校验。也就是说，整合算法已经能控制最终压缩比，但上游解析质量越高，合并案例的语义质量也会越好。

## 6. 教学完整性分析

源图谱中共有 1525 条关系，其中 `contains = 766`，`prerequisite = 759`，`prerequisite` 覆盖率约为 49.77%。这说明系统并不是只抽取孤立节点，而是保留了接近一半的学习先后关系。`contains` 关系负责维持“章节包含小节 / 主题包含知识点”的结构，`prerequisite` 关系负责维持“先学 A 再学 B”的教学路径。整合后图谱保留 308 条边，虽然数量减少，但边会随节点合并重写，避免因为合并节点而断开教学链路。

对教师来说，整合后的图谱可以先查看一级主题，再展开二级节点和知识点，符合从教材目录到具体概念的教学阅读顺序。对于系统来说，`prerequisite` 边也能服务后续学习路径推荐和 RAG 回答解释，例如当学生询问“为什么动作电位需要先学静息电位”时，可以从图谱边和教材切片中共同取证。

## 7. 知识冲突检测

新增的冲突检测会寻找“名称高度一致但定义文本差异较大”的节点。本次整合识别出 `conflict_001`：`第三节血栓形成` 在《05_病理学》和《07_病理生理学》中名称 token 重合度为 1.00，但定义文本重合度为 0.2701，低于 0.30 阈值。系统因此将其标记为潜在定义冲突，提示教师检查两本教材对该主题的口径、范围或教学侧重点是否不同。该结果会写入 `GraphIntegrationResult.conflicts`，并挂载到整合节点的 `metadata.conflicts`，前端节点详情面板会以红色警示块展示。

## 8. 结论

本次 7 本教材整合达成核心验收目标：系统能生成节点和边列表，输出 `merge / keep / remove` 决策，给出每项决策理由，并将整合后内容压缩到 30% 以内。当前结果也暴露了一个明确优化方向：继续加强 PDF 目录页、出版信息和泛化章节标题过滤，减少非知识点进入图谱。总体上，跨教材整合链路已经可运行、可解释、可压缩，并能通过前端聊天界面接受教师反馈进行二次修正。
