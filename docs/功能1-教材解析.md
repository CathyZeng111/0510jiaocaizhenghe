# 功能 1：多格式教材加载与解析

## 范围

当前功能支持上传 PDF、Markdown、TXT、DOCX 教材，并解析为统一的 `Textbook` 结构：

- 教材元数据：`textbook_id`、文件名、标题、页数、总字数
- 章节结构：章节 ID、标题、页码范围、正文、字数
- 上传结果：成功/失败状态、错误信息、解析后的教材对象

## 内存教材仓库

`backend/app/textbook_store.py` 提供进程内教材仓库 `textbook_store`。上传解析成功后，`parse_upload()` 会调用 `cache_upload_result()` 将结果写入仓库，供后续知识图谱和 RAG 复用。

仓库当前提供：

- `list_textbooks()`：列出已缓存教材
- `get_textbook(textbook_id)`：读取教材完整结构
- `get_chapters(textbook_id)`：读取章节列表
- `get_chunks(textbook_id=None)`：读取按章节切分的检索片段
- `get_rag_documents(textbook_id=None)`：输出 `{id, text, metadata}` 形式的 RAG 文档
- `get_graph_seed(textbook_id)`：输出教材节点、章节节点和解析质量信息，作为图谱构建输入
- `clear()` / `delete_textbook()`：清理内存缓存

仓库使用解析结果签名去重；如果不同教材复用了同一个上传序号生成的 `book_01`，仓库会为后续教材分配带短哈希后缀的唯一 ID，避免覆盖。

## 解析质量信号

`backend/app/parser_quality.py` 提供 `assess_textbook()` 和 `assess_upload_result()`，输出：

- `score`：0 到 1 的质量分
- `level`：`good`、`warning`、`poor` 或 `failed`
- `warnings`：可读风险提示
- `metrics`：章节数、空章节数、短章节数、重复标题数、页码异常等指标

这些信号不会阻断上传，但图谱和 RAG 可以在消费前决定是否提示用户重新上传、人工校正章节，或降低该教材的召回权重。

## 当前限制

- 缓存是进程内内存态，服务重启后会丢失。
- 多 worker 部署时，每个 worker 拥有独立缓存；生产环境应替换为数据库或对象存储。
- 当前 RAG chunk 只按字符窗口切分，还没有加入 embedding、向量库索引或语义分段。
- 图谱输出是 seed 数据，还没有执行实体抽取、关系抽取和消歧。

## 后续接入建议

1. 图谱构建接口从 `textbook_store.get_graph_seed(textbook_id)` 读取教材和章节节点。
2. RAG 索引任务从 `textbook_store.get_rag_documents(textbook_id)` 读取片段并生成 embedding。
3. 如果引入持久化层，优先保留当前仓库 API，再替换底层实现，减少上层调用改动。
